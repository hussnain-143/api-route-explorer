Troubleshooting Guide

Find diagnostic steps and practical solutions for common questions regarding route discovery, HTTP network errors, and authentication.

1. "No routes found in workspace"

If opening your project results in an empty tree, review these common causes:

  • Workspace Root Location: Ensure you opened the directory containing your backend code (or `package.json`) directly in VS Code. If your backend is in a subfolder (e.g. server/ or backend/ within a monorepo), open that subfolder or ensure it is included in your multi-root workspace.
  • Supported Framework Syntax: Verify your project uses supported routing patterns for Express, Next.js, Fastify, or NestJS. Custom helper functions that wrap route declarations in dynamic closures cannot always be resolved statically without runtime execution.
  • Trigger Manual Re-scan: Open the Command Palette (Cmd+Shift+P) and run API Route Explorer: Discover Routes.

2. Connection Error: ECONNREFUSED

HTTP Client Error MessageNetwork Failure
Error: connect ECONNREFUSED 127.0.0.1:5000

Explanation: The extension tried to send an HTTP request to the designated address, but no operating system process is listening on that port.

Solution:

  1. Open your integrated terminal and boot your backend dev server (e.g. npm run dev or node server.js).
  2. Confirm the port your backend binds to (e.g. 3000, 5000, 8080).
  3. In the HTTP Client address bar, ensure the base URL and port match your active server (e.g. http://localhost:5000).

3. 404 Not Found from Server

Explanation: API Route Explorer discovers routes as defined in your code files. However, at runtime, your server might apply a global prefix or mount router modules under parent paths that differ from the file path.

Common Causes:

  • Express Global Prefix: app.use('/api/v1', router) mounts sub-routes with an /api/v1 prefix.
  • NestJS Global Prefix: app.setGlobalPrefix('api') in main.ts prepends /api to all controller paths.
  • Fastify Prefix Options: fastify.register(userRoutes, { prefix: '/users' }).

Solution: Verify that the resolved URL in the HTTP Client includes the required global mount prefix before clicking Send.

4. 401 Unauthorized / 403 Forbidden

Explanation: API Route Explorer is an honest, secure developer client. It does not bypass server authentication middleware or invent credentials.

Solution:

  • In the HTTP Client, switch to the Headers tab.
  • Add your required credentials, such as: 
    Authorization: Bearer YOUR_DEVELOPMENT_JWT_TOKEN
  • For cookie-based auth, provide the Cookie header manually.

5. Request Timeout

Explanation: The server did not respond within the default client timeout period (e.g. backend breakpoint hit in debugger, unhandled promise hang, or infinite loop in handler).

Solution:

  • Check your debugger to see if execution is currently paused on a breakpoint.
  • Ensure your route handler sends a response (e.g. res.json(...) or return data) instead of hanging.
  • Click the Cancel button in the HTTP Client to immediately abort the hanging socket connection.
