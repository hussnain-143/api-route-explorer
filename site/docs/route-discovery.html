Route Discovery Engine

API Route Explorer uses non-executing, static Abstract Syntax Tree (AST) analysis to index API routes with zero runtime side effects.

How Static AST Parsing Works

Unlike dynamic tools that require running your server or injecting middleware, API Route Explorer parses code statically using TypeScript and JavaScript compilers.

  • No Server Execution: Your backend server does not need to run for routes to be discovered.
  • Zero Side Effects: Database connections, third-party API calls, and startup scripts are never triggered.
  • Sub-second Speed: Capable of scanning 4,700+ routes in under 100 milliseconds.

Supported Route Patterns

1. Express.js

Detects verbs on app and router instances (get, post, put, delete, patch, all). Resolves nested router mounting (e.g. app.use('/api', router)).

2. Next.js App Router

Scans app/api/**/route.ts and app/api/**/route.js files, extracting named HTTP verb function exports and dynamic folder parameters ([id], [...slug]).

3. Next.js Pages Router

Maps files inside pages/api/** to endpoints, supporting default function exports.

4. Fastify

Parses instance methods (fastify.get, fastify.post) as well as full fastify.route({...}) configuration calls and plugin prefix registration.

5. NestJS

Scans classes decorated with @Controller() and methods with @Get(), @Post(), @Put(), @Delete(), and @Patch().

Incremental File Watchers

API Route Explorer registers debounced file system watchers on your workspace. When you add, edit, or delete a route file, the tree automatically updates in the background without needing a manual scan.
